# 许可证选择记录

> 项目所有者已选择 **Apache License 2.0**。本页保留选择依据，作为项目决策记录。

代码只有在项目所有者授予明确许可证后，才是法律意义上的开源项目。公开 GitHub 仓库但没有 `LICENSE`，默认仍是“保留所有权利”，其他人通常无权复制、修改和再发布。

## 两个合适的选择

| 项目 | MIT | Apache License 2.0 |
|---|---|---|
| 允许商用、修改和再发布 | 是 | 是 |
| 必须公开衍生源码 | 否 | 否 |
| 专利授权条款 | 简单/未明确展开 | 明确的贡献者专利授权与终止条款 |
| NOTICE 机制 | 无强制机制 | 保留适用的 NOTICE 信息 |
| 文本长度 | 很短 | 较长 |
| 企业法务熟悉度 | 很高 | 很高 |

## 最终决定

DIANA-MCP 采用 **Apache License 2.0**。它仍是宽松许可证，同时对贡献相关专利授权和 NOTICE 处理更明确。

如果项目所有者更重视最短文本和最低合规负担，MIT 也很合适。

## 与 DIANA 的关系

开源许可证只覆盖本仓库中项目所有者有权授权的代码和文档，不会给使用者授予：

- DIANA 软件许可证；
- DIANA 用户手册的再分发权；
- DIANA 商标权；
- 客户模型或第三方经验材料的权利。

因此无论选择 MIT 还是 Apache-2.0，都应保留 [NOTICE.md](../../NOTICE.md) 中的独立项目和第三方内容声明。

## 已落实

1. 仓库根目录已添加标准 `LICENSE` 全文；
2. `pyproject.toml` 已增加 SPDX 表达式和许可证文件声明；
3. 中英文 README 已链接许可证；
4. `NOTICE.md` 已保留独立项目、商标和第三方内容声明；
5. GitHub 仓库创建后，还需在 About 和首个 Release 中确认许可证显示正确。

许可证是项目所有者的法律决定；本说明不是法律意见。如项目涉及雇佣成果、单位资产或已有合同，应先确认代码权属。
